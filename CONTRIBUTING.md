# Contributing

Contributions are welcome. Keep manifest and documentation changes focused and easy to validate.

## Workflow

1. Branch from `master`.
2. Make one logical change per pull request.
3. Keep JSON valid and preserve the existing manifest structure and naming conventions.
4. Verify changed download URLs, versions, hashes, and architecture-specific fields where applicable.
5. Describe what changed and how the manifest was validated in the pull request.

Do not commit credentials, local Scoop state, downloaded installers, caches, or generated files that are not part of the bucket itself.
